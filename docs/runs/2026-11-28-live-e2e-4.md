## What changed (each with a test that failed first)

| # | Open item | Root cause found | Fix (commit) |
|---|---|---|---|
| 1 | Marketing A5 failed 5× | the campaign curve sat on an arrival `rate` scoped by `self.customer_segment`; the record does not exist when the rate is evaluated, so the scope never matched and the curve stayed at baseline (−0.5 % three times). The compiler never checked scopes on `rate` / derive `p` | compiler checks those scopes and says how to target a category (`167224b`) |
| 1 | Podpora oscillated (root-rule ↔ gate errors) | the agent saw only the last attempt, so a regression became the base of the next one | A5 edits its **best** attempt, sees the history with recurring errors marked, and a failed expectation comes with the lever reach (`167224b`) |
| 2 | Segment stories scored 0 | A4 had to invent `CUS-001…005`; scoring matched ids only | `StoryPoint.segment {field, values}`, demanded by the compiler for category-scoped curves; stored in `truth.story_points.segment_values`; scoring matches values (`7d75edd`) |
| 3 | Causal effect −8.6 % vs −10 % | sales sit on a branch's success outcome: diluted volume (v1 already uses 5 % for it); seed 42 also hid that sale moved only −1..−5 % on seeds 1..5 | 5 % for success-outcome paths (`6353f15`); causal gate demands ≥ 4/5 seeds, 4b gets 3 rounds (`f61f8e4`) |
| 4 | ECONNRESET during engine runs | engine + store blocked the event loop (1–10 s) | `Ports.noiser.run` async, engine in a `worker_threads` worker; lag at scale 3: engine 15 ms, store 69 ms (`dd5756e`) |
| 5 | Podpora replay missed the cache (found here) | detective SQL without `ORDER BY` returned rows in a thread-dependent order | sandbox runs single-threaded (`0acc557`) |
| 5 | React duplicate-key warnings in podpora (found here) | noise duplicates repeat row ids in the table preview | key = id + position (`0acc557`) |
| 6 | Session contract in a draft file | – | moved to `@s2d/schema/api` (`CascadeEvent` in `/artifacts`) (`ba1b65b`) |

Precision stays one finding per story point: true downstream findings count as unmatched, so precision
is a lower bound (decision in `docs/decisions.md`).
