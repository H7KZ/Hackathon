# Live end-to-end run #3 — 2026-11-28 (full integration, multiple use cases)

The first run of the **whole integrated product** (UI → API → cascade → noiser → DuckDB → evidence →
what-if → compare → detective) with real LLM calls on several prompts, through the API harness and
through a real browser. Every failure was diagnosed; the ones that were bugs in our code are fixed
on branch `feat/integration-all` and re-run. Two remaining limits are LLM/model behaviour, listed
with their evidence.

**Short version**

- 4 of 5 v1 prompts now go end to end on Sonnet 5.5: data that carries the story (every expectation
  passes), 2 what-ifs each with a comparison, the blind detective, and the UI shows all of it.
- A brand-new domain typed into the browser (coffee chain) went through the whole UI live in 3.9 min.
- The offline demo (`pnpm demo`, no network) replays the "Dodavatel" example in the browser,
  including detective and what-if.
- Live runs found **9 bugs in our code**, all fixed with a test that failed first (list below).
- Still open: `podpora` fails A5 on Sonnet (passes on GPT-5); the experimental causal design fails its
  story gate on effect strength (−8.6 % vs −10 % needed); segment-level stories score detective
  recall 0 although the detective finds them.

## Setup

- Branch `feat/integration-all`. API started per design with every LLM step pinned to one model
  (`. scripts/live-env.sh`), separate `RUNS_DIR` per API process.
- Harness: `node scripts/live-e2e.mjs --api <url>` drives each prompt like the UI does: draft →
  approve with the editor's default settings (seed 42, noise 2 % missing / 1 % duplicates / hourJitter,
  all hypotheses) → if A5 gives up, press "Generovat data" once more → evidence + tables → what-if ×2
  (the UI's suggested questions) → compare → detective. JSON reports in `out/live-e2e/` (gitignored).
- Browser: Playwright `E2E_REAL=1` (`services/frontend/tests/e2e/real.spec.ts`) types the prompt,
  waits for the agents, clicks "Generovat data", opens every tab, runs the detective and a what-if.
  `review.spec.ts` re-opens finished live sessions and screenshots every panel.
- Models: `anthropic:claude-sonnet-5-5` (main), `openai:gpt-5` (cross-check). Groq key invalid.

## Bugs found by the live runs and fixed

| # | Symptom in the live run | Cause | Fix (commit) |
|---|---|---|---|
| 1 | dodavatel: A5 failed 5/5, alternating "curve not used" / "curves only on roots" | flat 04_story curves (no segments) were demanded like story levers | flat curves are constants (`9c943cd`) |
| 2 | causal: code derived "lost sales **fall**", data showed +638 % | LLM marked both branch outcomes positive; the convention "failure = negative" was assumed, never checked | causal-map check (`9c943cd`) |
| 3 | elektro session showed `interrupted` mid-job | two API processes shared `runs/`; each startup marked the other's jobs interrupted | `RUNS_DIR`, e2e uses `runs-e2e/` (`e505994`) |
| 4 | pressing "Generovat data" after a failed A5 replayed the same failure | same prompt → disk cache → same answers | A5 resumes from its last rejected attempt (attempt 6…) (`f000425`) |
| 5 | generation progress card listed A1–A3 again | approve re-emits cached steps | only the draft card grows (`f000425`) |
| 6 | podpora: root-rule message said what is wrong, not where to go | no upstream root named | message names the roots (`aa974e2`) |
| 7 | `openai:*` failed at 02_model ("oneOf is not permitted") | zod unions → JSON Schema `oneOf` | rewritten to `anyOf`, non-strict schema (`43d6068`) |
| 8 | offline demo: what-if missed the cache in every new session | the prompt embedded `meta.id` = session id | id kept out of the prompt (`464db38`) |
| 9 | podpora: A5 oscillated 10 attempts | 4 bending curves, 1 root; redundant / outcome curves were demanded | such curves may stay unused; the story gate still checks the effect (`cec8c66`) |

UI issues found in the screenshot review and fixed: rare events indexed to 4 000 on the overview
chart (now each series vs its own maximum, damped ranking, one line per table), `ts` duplicates of
every series (hourJitter), TIMESTAMP shown without time, what-if markers stuck at the old date
(`f3d4c80`, `db704ce`).

## Still open (not integration bugs)

- **Podpora on Sonnet:** A4 plans four bending curves for one lever; even with fix 9, Sonnet keeps
  moving `issue_rate` onto the downstream parameter. GPT-5 builds a valid scenario for the same
  prompt. Next step: an A4 check that a phase ≥ 2 outcome point gets no bending curve.
- **Causal design:** direction is right after fix 2; the effect on sales is −8.6 % against a −10 %
  threshold after both 4b repair rounds. Needs calibration of `MIN_CHANGE` or more 4b rounds. v1 stays
  the default.
- **Segment stories score 0:** for "campaign customers" A4 has to name entity ids, invents
  `CUS-001…005`; the detective correctly reports the "kampaň" segment and the exact date, but scoring
  matches ids only. Needs story points that can name a categorical value.
- **Precision 25–33 %:** the detective's extra findings are true downstream effects (backorders,
  cancellations) of the one scored story point; scoring counts one match per point.

## Offline demo

`pnpm demo` starts API + UI with `LLM_OFFLINE=1` and every step pinned to Sonnet 5.5. The "Příklad:
Dodavatel" example replays draft → data → detective → what-if from `.cache/llm/` (verified in the
browser with `E2E_REAL=1 LLM_OFFLINE=1`). Other prompts, edited stories or new questions need a live
model; the UI then says so in Czech instead of failing silently.

## How to reproduce

```
. scripts/live-env.sh
API_PORT=4400 RUNS_DIR=runs-live pnpm --filter @s2d/api start
node scripts/live-e2e.mjs --api http://localhost:4400 --runs runs-live
cd services/frontend && E2E_REAL=1 npx playwright test real        # browser, live
cd services/frontend && E2E_REAL=1 LLM_OFFLINE=1 npx playwright test real   # browser, offline replay
```
